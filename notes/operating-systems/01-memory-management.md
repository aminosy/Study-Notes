# 内存管理基础：分页、分段、虚拟内存与地址翻译

本篇梳理操作系统内存管理的核心机制：为什么需要虚拟内存、分页与分段如何组织地址空间、页表与 TLB 如何加速翻译、page fault 发生时系统做了什么。

## 1. 为什么需要虚拟内存 (virtual memory)

如果让每个进程直接使用物理地址，会遇到三个无法回避的问题：

| 问题 | 具体表现 |
| --- | --- |
| 隔离性 (isolation) | 进程 A 可以读写进程 B 的内存，一个 bug 就能破坏整个系统 |
| 重定位 (relocation) | 程序编译时无法知道自己会被加载到物理内存的哪个位置 |
| 容量 (capacity) | 物理内存装不下所有进程的工作集时，无法优雅地换出 |

虚拟内存用一层**地址翻译 (address translation)** 同时解决这三点：每个进程看到一套自己独占的、从 0 开始连续编号的虚拟地址空间 (virtual address space)，由硬件与操作系统协作映射到真实的物理页帧 (page frame)。

由此得到三个直接收益：

- **隔离**：进程无法构造出指向其他进程物理内存的虚拟地址（除非映射被显式共享）。
- **简化链接与加载**：可执行文件可以假定自己从固定虚拟地址开始，加载器只需建立页表映射。
- **按需分配**：虚拟地址可以先被保留 (reserve)，直到真正访问时才分配物理页，这就是 demand paging 的基础。

## 2. 分段 (segmentation)

分段的核心思想是：**地址空间按逻辑单元切分**，每一段有自己的基址 (base) 和界限 (limit)。

典型的段划分：code、data、heap、stack。一个逻辑地址表示为 `(段号, 段内偏移)`，翻译过程是：

```text
if offset >= limit:            # 越界检查
    raise SegmentationFault
physical = base + offset
```

分段的优点：

- 与程序员的直觉一致（代码段、数据段、栈段）；
- 天然支持段的共享与保护（代码段可标记为只读+可执行）；
- 段的增长可以独立进行（栈向下长、堆向上长）。

分段的缺点：

- **外部碎片 (external fragmentation)**：段的长度不固定，反复分配释放后物理内存被切得七零八落，剩余空闲空间总和可能够用但找不到连续区间；
- 需要复杂的空闲空间管理策略（首次适配 first-fit、最佳适配 best-fit、最差适配 worst-fit）。

现代通用操作系统（Linux、Windows）普遍采用**分页为主、分段为辅**的方案：x86-64 在 64 位模式下基本把段机制"扁平化"处理（所有段的 base 为 0、limit 拉满），实际隔离由分页完成。

## 3. 分页 (paging)

分页把虚拟地址空间和物理内存都切成**固定大小**的块：

- 虚拟侧的块叫**页 (page)**；
- 物理侧的块叫**页帧 (page frame)**；
- 两者大小相同，通常为 4 KiB，也有 2 MiB / 1 GiB 的 huge page。

固定大小带来一个关键好处：**没有外部碎片**，任何空闲页帧都能装下任何页。代价是产生**内部碎片 (internal fragmentation)**——一个 5 KiB 的对象需要占 2 个页，浪费约 3 KiB。

### 3.1 地址拆分

以 32 位、4 KiB 页、两级页表为例，一个 32 位虚拟地址被拆成三段：

```text
 31          22 21          12 11                      0
+--------------+--------------+-------------------------+
|  页目录索引  |   页表索引   |      页内偏移 offset     |
|  (10 bits)   |   (10 bits)  |        (12 bits)        |
+--------------+--------------+-------------------------+
      PDE             PTE              0 .. 4095
```

- 12 位偏移 ⇒ 页大小 2^12 = 4096 B = 4 KiB；
- 每个页表有 2^10 = 1024 个页表项 (PTE, page table entry)；
- 一个页表本身占 1024 × 4 B = 4 KiB，正好一个页。

这就是多级页表的精妙之处：**页表本身也被分页**，可以按需换出，不必为整个虚拟地址空间预留连续的物理内存。

### 3.2 页表项 (PTE) 里有什么

| 位 / 字段 | 含义 |
| --- | --- |
| 物理页帧号 (PFN) | 该页映射到哪个物理页帧 |
| Present / Valid | 该页当前是否在物理内存中；为 0 时访问触发 page fault |
| Read / Write | 是否可写，是写保护的硬件基础 |
| User / Supervisor | 用户态能否访问；为 0 时只有内核态可访问 |
| Accessed | 是否被访问过，供页面置换算法参考 |
| Dirty | 是否被写过；干净页换出时无需写回磁盘 |
| NX (No-eXecute) | 该页是否允许作为指令执行（与 DEP 相关，见 03） |
| Global | 标记为全局页时，切换地址空间不必刷新对应 TLB 项 |

### 3.3 多级页表的代价

以 64 位、4 级页表（x86-64 的 PML4 → PDPT → PD → PT）为例，一次地址翻译最多需要 **4 次内存访问**读页表，再加上第 5 次访问真正的数据。这显然不可接受，于是引入 TLB。

## 4. TLB (Translation Lookaside Buffer)

TLB 是 MMU 内部的一小块**地址翻译缓存**，保存最近使用过的 `虚拟页号 (VPN) → 物理页帧号 (PFN)` 映射。

一次内存访问的完整路径：

```text
CPU 产生虚拟地址 VA
        |
        v
   [ 拆分 VA 得到 VPN + offset ]
        |
        v
   TLB 中查 VPN ------------- 命中 (hit) ---------> 直接得到 PFN，访问物理内存
        |
     未命中 (miss)
        |
        v
   查页表 (多级，若页表项不在缓存还可能多次访问内存)
        |
        +--> PTE.Present == 1 ---> 填入 TLB，重试访问
        |
        +--> PTE.Present == 0 ---> 触发 page fault，交给内核处理
```

几个必须记住的细节：

- **TLB 是按进程隔离的**：切换地址空间（context switch）后旧映射失效，否则进程 A 可能读到进程 B 的物理内存。常见做法是刷新整个 TLB（简单但慢），或用 **ASID / PCID** 给 TLB 项打上地址空间标签，避免全量刷新。
- **TLB 通常不缓存页内偏移**：偏移不参与翻译，直接拼接即可，所以 TLB 只需存 VPN → PFN。
- **修改页表后必须让对应 TLB 项失效**：这是内核里常见的 `flush_tlb_*` 系列操作存在的原因。忘记失效会导致"改了页表但硬件还用旧映射"的诡异 bug。
- TLB 命中率对性能影响极大：TLB 未命中要额外 4 次（四级页表）内存访问，量级差异明显。这也是 huge page 有性能价值的原因——一个 2 MiB 大页只需要一个 TLB 项就能覆盖 512 个 4 KiB 页的地址范围。

## 5. 虚拟内存与按需分页 (demand paging)

**按需分页**的基本策略是"不到真正访问就不分配物理页"。进程启动时，内核只建立虚拟地址空间的描述（Linux 里是 VMA，virtual memory area），并不立刻分配页帧。

页面在系统中的状态可以用状态机描述：

```text
       访问未映射地址
   (1) 未分配 ---------------- 可能触发 SIGSEGV（取决于是否落在合法 VMA 内）
        |
        | 首次访问合法 VMA 内的页
        v
   (2) 已分配但不在内存 (Present=0)
        |
        | page fault -> 从磁盘/交换区读入
        v
   (3) 在内存中，干净页 (Dirty=0)
        |
        | 被写
        v
   (4) 在内存中，脏页 (Dirty=1)
        |
        | 内存压力下被置换
        v
   (2) 回到不在内存状态（脏页需要先写回 swap/文件）
```

对 Linux 而言还有一个重要的区分：

- **匿名页 (anonymous page)**：堆、栈等没有文件背书的页；换出时写入 swap 分区。
- **文件映射页 (file-backed page)**：来自可执行文件或 mmap 的文件；换出时若为干净页直接丢弃，下次缺页再从文件读。这也是为什么程序第一次运行时"冷启动"更慢——页缓存是空的。

## 6. 缺页中断 (page fault) 的完整流程

page fault 是一种**异常 (exception)**，不是中断。CPU 在翻译地址失败时保存现场并跳转到内核的处理函数。

```text
1. 硬件：翻译 VA 失败，PTE.Present == 0（或权限不符）
2. 硬件：把出错地址存入 CR2（x86），压入错误码，跳到 page fault handler
3. 内核：读取 CR2，判断该地址是否落在进程的某个合法 VMA 内
   ├─ 不在任何 VMA 内 → SIGSEGV（这是真正的段错误）
   ├─ 在 VMA 内但权限不符（如写只读页）→ 可能是 COW，否则 SIGSEGV
   └─ 在 VMA 内且合法 → 继续
4. 内核：找一个空闲物理页帧
   ├─ 有空闲帧 → 直接用
   └─ 无空闲帧 → 执行页面置换，选一个牺牲页 (victim)
        ├─ 牺牲页是脏页 → 先写回 swap 或文件
        └─ 牺牲页是干净页 → 直接回收
5. 内核：把所需内容读入页帧
   ├─ 文件映射页 → 从文件读（可能命中 page cache）
   ├─ 匿名页（曾被换出）→ 从 swap 读
   └─ COW 页 → 复制原页内容到新帧
6. 内核：更新 PTE（填入 PFN，设置 Present / 权限位），必要时失效旧 TLB 项
7. 内核：返回到出错指令，硬件重新执行该指令
   —— 注意是"重新执行"，不是"继续下一条"，因此处理过程必须对进程透明
```

这个流程解释了三个常见现象：

- **为什么缺页处理很慢**：至少一次磁盘 I/O，最坏情况还要先写回一个脏页，相当于两次 I/O。
- **为什么 COW 后立即写会变慢**：`fork()` 后父子进程共享只读页，第一次写触发写保护 fault，内核复制整页。`fork()` 本身很快，代价被推迟到了写入时。
- **为什么"内存不足"不一定立刻 OOM**：由于按需分页与过量提交 (overcommit)，虚拟内存申请成功不代表物理内存可用。真正危险的是访问时的缺页无法满足，此时才触发 OOM killer（Linux 的启发式选择）。

## 7. 页面置换算法

当没有空闲页帧时，必须选择牺牲页。经典算法与其关键性质：

| 算法 | 思路 | 关键结论 |
| --- | --- | --- |
| OPT / MIN | 置换未来最久不会被访问的页 | 理论最优，但需要未来信息，无法实现；用于作为基准衡量其他算法 |
| FIFO | 置换最早进入内存的页 | 实现最简单；存在 **Belady 异常**：增加页帧数反而可能增加缺页次数 |
| LRU | 置换最久未被访问的页 | 利用局部性，效果好；但精确实现需要每次访问都更新时间戳，开销大 |
| Clock / 二次机会 | 用 Accessed 位近似 LRU，环形扫描 | 实际系统常用，开销低，效果接近 LRU |

**局部性原理 (principle of locality)** 是所有置换算法有效的前提：时间局部性指刚被访问的页很可能再次被访问；空间局部性指相邻地址很可能被一起访问。如果程序的访问模式完全没有局部性（例如大数组的跨步访问），任何置换算法都救不了它，表现为**抖动 (thrashing)**——系统把绝大部分时间花在换页上，CPU 利用率反而下降。

## 8. 一次完整的地址翻译示例

设 32 位系统、4 KiB 页、两级页表，访问虚拟地址 `0x00403ABC`。

```text
VA = 0x00403ABC = 0000 0000 0100 0000 0011 1010 1011 1100 (binary)

拆分：
  页目录索引 (bit 31-22) = 0x001  = 1
  页表索引   (bit 21-12) = 0x003  = 3     # 0b0000000011
  页内偏移   (bit 11-0)  = 0xABC  = 2748

步骤：
1. 读 CR3 得到当前进程页目录的物理基址
2. 页目录[1] -> 得到二级页表的物理基址
3. 二级页表[3] -> 得到 PTE
4. 检查 PTE.Present（和权限位）
   - Present == 0 → page fault（走第 6 节的流程）
   - Present == 1 → 取出 PFN，假设为 0x1A2
5. 物理地址 = PFN * 4096 + offset = 0x1A2000 + 0xABC = 0x1A2ABC
6. 访问物理地址 0x1A2ABC；同时把 VPN(=0x00403) → PFN 写入 TLB
```

自己练习时可以把位运算拆得更细：`(VA >> 22) & 0x3FF` 得到页目录索引，`(VA >> 12) & 0x3FF` 得到页表索引，`VA & 0xFFF` 得到偏移。

## 小结

- 虚拟内存用一层翻译同时实现隔离、简化加载与按需分配。
- 分段按逻辑单元切分，灵活但有外部碎片；分页固定大小，无外部碎片但有内部碎片。现代系统以分页为主。
- 多级页表让页表本身可分页、可换出，代价是翻译需要多次访存，因此引入 TLB 缓存。
- page fault 不是错误，而是按需分页的正常机制；只有地址不在任何合法 VMA 内时才是真正的段错误。
- 页面置换算法的效果依赖程序的局部性；没有局部性的程序会抖动。
- 一切内存安全问题的根源，都可以回溯到"这一段虚拟地址映射到了什么物理内容、有什么权限"这个基本问题上——这正是下一篇的主题。
