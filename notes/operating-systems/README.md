# 操作系统学习笔记

操作系统（Operating Systems）方向的自学笔记索引。重点放在内存管理与内存安全，兼顾底层机制与工程防御视角。

## 这个板块在学什么

操作系统课程对我来说最难的不是背概念，而是把「课本上的抽象机制」和「程序真正跑起来时的行为」对上号。所以这个板块的笔记有两条主线：

1. **机制主线**：内存怎么管、地址怎么翻译、缺页时发生了什么——这是理解一切内存问题的地基。
2. **安全主线**：既然内存是程序共享的稀缺资源，那么「管错了」会出什么问题、业界又用什么手段防——从漏洞成因到防御策略，再到「配置检查为什么防不住运行时问题」。

## 学习路线

建议按下面的顺序推进，每一步都要求「能自己画图讲出来」才算过关。

```text
第一步：建立地址空间的概念
  01-memory-management.md 的前半部分
    - 为什么需要虚拟内存
    - 分页 vs 分段
    - 页表结构与多级页表
  过关标准：能画出 32 位两级页表下，一个虚拟地址被拆成几段、每段查什么

第二步：理解「访问内存」这个动作的全过程
  01-memory-management.md 的后半部分
    - TLB 命中 / 未命中
    - page fault 的完整处理流程
    - 地址翻译的端到端流程图
  过关标准：给定虚拟地址，能口述从 CPU 到物理内存的每一步

第三步：从「机制」转向「机制被破坏」
  02-memory-vulnerabilities.md
    - 栈帧布局与返回地址覆盖
    - 堆元数据与 UAF / double free
    - 类型与长度不匹配（整数溢出、格式化字符串）
    - 并发下的 TOCTOU
  过关标准：能指出每一类漏洞破坏的是哪个不变量

第四步：防守方视角
  03-defense-strategies.md
    - 编译期 / 链接期 / 加载期 / 运行期四层防御
    - 每种防御绕过思路的直觉（了解即可，重点是知道它防的是什么）
    - 工具链：编译器 sanitizer、静态分析、动态分析
  过关标准：能说明 ASLR 与 NX 分别让哪一种攻击变难，为什么它们互补

第五步：把「检查」和「执行」分开看
  04-config-vs-runtime-gap.md
    - 配置/校验发生在什么时刻，作用于什么输入
    - 运行时真实输入空间有多大
    - 一套六步分析框架
  过关标准：能对一个陌生系统，写出「配置声明了什么 / 运行时实际做了什么 / 差距在哪」三段论
```
